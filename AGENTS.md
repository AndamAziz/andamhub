- Android CI publishes APK/AAB downloads through GitHub Releases, not Actions Artifacts, because artifact-storage quotas can block otherwise successful builds.
- Android OAuth uses Lovable's allowed `lovable://oauth-callback` deep link with state validation and Capacitor Browser/App plugins so social sign-in returns to the installed app.
- Android player fullscreen portals the existing video stage to the document body so WebView rotation cannot trap it inside the page layout.
- Live TV visual work in `public/andam.html` must remain presentation-only; preserve playback engines, relay/proxy calls, authentication, data sources, and routes.
- M3U request headers stay inside encrypted playback tokens and are allowlisted server-side, because protected channels must work without exposing provider metadata.
- Exception: `/api/public/iptv?action=play` also returns `direct` {url, headers} (every channel of a public playlist, and header-protected channels of any playlist) so the native Android app (`android-native/`) can request them itself; Xtream provider URLs and credentials are never exposed.
- The native app (`android-native/`) has a TV layout (`ui/Tv.kt`, `LocalTv`): left menu, category pane, search button instead of a text field, focus rings via `tvFocus`; the player maps remote keys in `PlayerActivity.dispatchKeyEvent`. Keep new clickable UI focusable with a visible focus ring.
- Windows app: `windows-app/` (Electron) opens https://ip.andam.uk in its own window; `.github/workflows/windows.yml` builds `Andam-Setup.exe` on windows-latest and republishes the rolling **pre-release** `windows-latest` (never "latest", so the Android updater keeps seeing Android builds). The app auto-updates from that release via electron-updater (generic provider).
- Windows app plays through a bundled mpv ("Andam Player", `windows-app/mpv/`, downloaded in CI by `scripts/get-player.js`). The website detects `window.andamDesktop.player` and hands streams to it in `lvPlay` (deskPlay); "Play here instead" / `localStorage andam.deskPlayer=0` keeps the in-page player. `/api/public/download?app=android|windows` redirects to the newest installer.
- Exception 2: for every Xtream provider, `play`/`series_info` also return the provider's own `direct` link when the caller passes `device=1` (Android and Windows apps only). The apps play it straight from the viewer's device first and keep the relay as fallback; the website never asks for it and always uses the relay.
- Live timeline: Android shows a seek bar / ±15 s / "-mm:ss LIVE" pill only when the live stream has a seekable window (HLS playlists); ExoPlayer cannot seek in progressive live MPEG-TS, so `.ts` channels keep the plain live view plus catch-up (`xtream?action=catchup`, provider timeshift on its own clock) for channels with `tv_archive`. The website rewinds inside the playlist window (hls.js) or what it buffered (mpegts.js, ~4 min); Andam Player (mpv) inside its demuxer cache. Never change how live streams are opened or retried for this.
- Film/series pages use `xtream?action=details&lang=` and `action=season` (TMDB via `TMDB_API_KEY`, optional; provider poster/story first). Subtitles: `/api/public/subtitles` (OpenSubtitles via `OPENSUBTITLES_API_KEY`); Kurdish (Sorani) is translated by free Google Translate on the viewer's device/browser (`kurdish-source` → translate → `kurdish-upload`, stored once for everyone) or on the server by Claude (`ANTHROPIC_API_KEY`) / Gemini. All keys live in server env vars, never in the apps or the repo.
- Player controls are one layout on every platform (Android `PlayerActivity.Controls`, website `controlsMarkup`, mpv `input.conf`): `[previous] [-15 s] (play) [+15 s] [next]`. Previous/next = channel on live TV, episode on series (never wrapping); ±15 s (`SKIP_MS` / `SKIP` / `seek ±15`) wherever the stream can be sought (films and episodes; never on live TV; dimmed only when the file really cannot be sought; a "Next episode" pill appears in the last 45 s of an episode. Presentation only: never touch how streams are opened or retried.
- TMDB search queries keep Persian letters as written (آ is not folded into ا for the query; `unify`/`norm` fold only for comparing) and add a variant with آ restored at word starts, because playlists often drop the madda ("اتش بس" → "آتش بس").
- Films / episodes: some panels refuse requests that carry a `Range` header (404/416/5xx) while serving the same file without it (live TV never sends Range, so only films broke). The Android app opens films WITHOUT a forced Range header (do not add one), and `xtream-play` retries a refused ranged request once without `Range` (browsers always send it). No emulated seeking, and no status pills ("Reconnecting…", "Trying another route…") on films/episodes; a subtitle change never restarts a film that cannot be sought.
- Provider accounts are often limited to ONE connection at a time: never open extra test connections to the provider before or during playback (a probe made ExoPlayer's own request get refused, and the busy account then failed on the website and Windows too). The only pre-play request is `resolveRedirects` (bytes 0-0, closed at once). Player settings → "Stream" shows the route and whether the file has a known length / can be sought.
- Speed: hot server reads are remembered in memory per worker (`src/lib/memo.server.ts`): unlocked access 20 s (`resolveAccessCached`; locked answers never cached), provider/playlist rows 30 s, admin overrides 30 s, playlist channels 5 min, provider category/channel/film/series lists 5 min (lists over 20 000 items are not kept). Long website lists (`paintChunks`) draw the first 120 rows and the rest as the viewer scrolls; never paint thousands of rows up front.
- Website live TV (Xtream): each `xtream?action=live` item carries `kind` from the provider's own list (`direct_source` empty → 'ts' classic panel, …m3u8 → 'hls' redirecting panel, else ''). `playById` passes it as `nextKnown`, so `lvPlay` starts mpegts.js / hls.js at once with NO `probeKind` request (the probe was a second provider connection and one-connection accounts held back the real stream); unknown kinds still probe. For 'hls' channels the website passes `kind=hls` to `xtream?action=play`, which then returns the `.m3u8` link as `play` (and `.ts` as fallback): its redirect is resolved before the manifest's relative paths are rewritten (the `.ts` first hop skips the redirect probe, so redirecting panels like ARYA1 broke). An mpegts error before anything played tries the `.m3u8` route first. A silent `.ts` moves to the playlist after 30 s.
- "All categories" (Live TV, IPTV, Movies, Series; Android phone + TV, website, Windows): one section per provider category in the provider's order — header (name, count, "See all"), a short vertical list of channel rows (8) or a poster grid (12), then a full-width "See all" that opens that category. Never horizontal rows, and categories are always chosen from the dropdown (Android `CategoryBar` also on TV instead of the side pane; website `.catsel` on every width, no chip row). Search or a picked category shows the flat list/grid. Android: `CategorySections.kt` (`groupByCategory`, `SectionHeader`, `SeeAllRow`); website: `groupSections` / `paintSections` / `chTile` (`.catsecs`, `.csrow`, `.chtile`), sections paint lazily.
